# Bellwether Parallel Buildout Plan

The next pass fills in three useful slices without pretending this portfolio project is a production platform. Each slice lives on its own branch, has focused tests, and can be merged independently.

## Global Constraints

- Keep this a focused single-chain, single-contract project; do not add multichain frameworks or deployment infrastructure.
- Preserve the existing in-memory chain store and its deterministic replay behavior.
- Use test-driven development: capture a focused failing test before implementation, then run the full repository check once before committing.
- Go owns chain and ingestion behavior. Python owns experiment orchestration only and must never compute model features.
- Do not add real wallet keys, provider credentials, market addresses, or claimed benchmark/model results.
- Keep public APIs small and documented. Prefer standard-library code unless an external type is required at the RPC boundary.

## Task 1: Track finality and reject unsafe deep reorgs

**Branch:** `soham/finality`

**Files:**

- Create: `internal/chain/finality.go`
- Create: `internal/chain/finality_test.go`
- Modify: `internal/chain/chain.go`

Add explicit `seen`, `safe`, and `finalized` levels for stored blocks. The store must allow finality to move forward, reject regressions and unknown blocks, and expose the latest safe/finalized checkpoint. A reorg may replace unfinalized history, but it must return a distinct `ErrResyncRequired` without mutating state when the common ancestor is missing, below the finalized checkpoint, or deeper than a caller-supplied retained-depth limit. Keep the current `Reconcile` API working; add a small bounded reconciliation entry point rather than putting RPC logic in the chain package.

Tests must cover monotonic finality, invalid marking, normal shallow reconciliation, finalized-history protection, depth-limit resync, atomic rejection, and checkpoint lookup. Commit as `feat: track finality and deep reorg resync`.

## Task 2: Add bounded Base log backfill

Define the narrow RPC interface needed around go-ethereum's `FilterLogs`. Implement a synchronous, context-aware backfiller for one configured contract address and topic set. It should request ascending inclusive block ranges, halve the current range after provider errors down to a configured minimum, grow it gradually after success up to a configured maximum, and emit logs in deterministic block/transaction/log order. Tests must use a fake client and cover inclusive batch boundaries, adaptive shrinking and recovery, stable output ordering, invalid configuration, and cancellation. Commit as `feat: add adaptive Base log backfill`.

## Task 4: Add the point-in-time feature engine

**Branch:** `soham/feature-engine`

**Files:**

- Create: `internal/features/features.go`
- Create: `internal/features/features_test.go`
- Create: `internal/features/engine.go`
- Create: `internal/features/engine_test.go`

Implement the five named features in Go with one documented pure function per feature: YES implied probability as `noReserve / (yesReserve + noReserve)`, recent trade-flow imbalance as signed YES-vs-NO volume divided by total absolute volume over a fixed event-count window, liquidity depth as the smaller outcome reserve, non-negative seconds to resolution, and block lag since the market's last update. Reject non-finite/negative reserves, non-positive trade amounts, invalid finality levels, backward event order, and snapshots before the latest applied update.

Create a small stateful engine for one market. Updates carry block number, log index, block timestamp, pool reserves, optional trade direction/amount, resolution time, and `chain.Finality`; snapshots carry the same point-in-time metadata and the five values. Applying an update changes state; taking a snapshot computes all five functions from only the already-applied state. Include a batch replay helper that uses the same `Apply` and `Snapshot` methods as a live caller rather than reimplementing feature math.

Tests must be table-driven where cases naturally share a contract. Cover exact feature math, zero-volume behavior, time clamping, event ordering, snapshot-before-update rejection, finality propagation, flow-window eviction, a two-market rejection guard (the engine is deliberately single-market), no mutation after rejected input, and element-for-element equality between manual streaming calls and the batch replay helper. Do not add Parquet, RPC types, concurrency, models, or benchmarks. Commit as `feat: add point-in-time feature engine`.

## Task 5: Decode the Bellwether fixture market events

**Branch:** `soham/market-decoder`

**Files:**

- Create: `internal/market/abi.go`
- Create: `internal/market/events.go`
- Create: `internal/market/decoder.go`
- Create: `internal/market/decoder_test.go`

There is no official Coinbase prediction-market contract or ABI on Base. Define and label a minimal Bellwether Base Sepolia fixture ABI for three events only: `Trade(bytes32 indexed marketId,address indexed trader,bool yes,uint256 amount,uint256 yesReserve,uint256 noReserve,uint64 resolutionTime)`, `LiquidityChanged(bytes32 indexed marketId,uint256 yesReserve,uint256 noReserve,uint64 resolutionTime)`, and `MarketResolved(bytes32 indexed marketId,bool outcome)`. This decoder is an integration fixture, not a claimed Coinbase/Kalshi integration.

Create typed immutable-by-convention Go event values using `internal/base` domain `Address`, `Hash`, and `Log` at the public boundary. Preserve uint256 numeric values as fresh `*big.Int` values and Unix resolution time as `uint64`; do not convert them to float features here. A decoder is configured for one non-zero contract address, rejects logs from other addresses, identifies events by topic zero, validates indexed-topic counts and ABI data, and returns a distinct unknown-event error. Do not expose go-ethereum types outside the ABI implementation files and do not modify `internal/chain.Event` in this task.

Tests must synthesize logs from the ABI rather than hand-writing encoded data. Cover each event, indexed market/trader extraction, full uint256 preservation above 64 bits, wrong contract, unknown or missing topic zero, missing indexed topics, malformed data, and proof that returned big integers/data do not alias the input or another decode. Do not add deployment scripts, RPC calls, Solidity, feature computation, persistence, or CLI code. Commit as `feat: decode fixture market events`.

## Task 6: Add bounded live Base log subscription

**Branch:** `soham/live-subscription`

**Files:**

- Modify: `internal/base/client.go`
- Modify: `internal/base/backfill.go` only to share existing RPC/domain conversion helpers when useful
- Create: `internal/base/live.go`
- Create: `internal/base/live_test.go`

Extend the narrow RPC seam with the go-ethereum `SubscribeFilterLogs` shape and implement a synchronous `Run(ctx, emit)` live-log consumer for the same one-address/topic filter used by backfill. It owns a configured positive-size bounded log channel, converts every RPC log to the existing domain `Log`, invokes the emitter synchronously so a slow consumer applies backpressure, returns emitter/subscription errors with context, returns `ctx.Err()` on cancellation, and always unsubscribes. A closed log channel or subscription error channel without a reported error returns a distinct `ErrSubscriptionClosed`. Do not reconnect or backfill gaps in this task.

The implementation must not start its own goroutine or close a channel it did not create for sending. Deep-copy topic filters at construction and for the subscription query just as backfill does. Tests use fake client/subscription values and deterministic handshakes (timeouts only as deadlock guards) to cover configured filters, ordered delivery/domain conversion, bounded backpressure, cancellation, subscribe error, subscription error, emitter error, channel closure, unsubscribe on every exit path, and caller/client topic mutation. Do not add WebSocket dialing, retries, metrics systems, workers, CLI, or credentials. Commit as `feat: add bounded live log subscription`.
