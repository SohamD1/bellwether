# Bellwether Parallel Buildout Plan

The next pass fills in three useful slices without pretending this portfolio project is a production platform. Each slice lives on its own branch, has focused tests, and can be merged independently.

## Global Constraints

- Keep this a focused single-chain, single-contract project; do not add multichain frameworks or deployment infrastructure.
- Preserve the existing in-memory chain store and its deterministic replay behavior.
- Use test-driven development: capture a focused failing test before implementation, then run the full repository check once before committing.
- Go owns chain and ingestion behavior. Python owns experiment orchestration only and must never compute model features.
- Do not add real wallet keys, provider credentials, market addresses, or claimed benchmark/model results.
- Keep public APIs small and documented. Prefer standard-library code unless an external type is required at the RPC boundary.

## Task 1: Track finality and reject unsafe deep reorgs

**Branch:** `soham/finality`

**Files:**

- Create: `internal/chain/finality.go`
- Create: `internal/chain/finality_test.go`
- Modify: `internal/chain/chain.go`

Add explicit `seen`, `safe`, and `finalized` levels for stored blocks. The store must allow finality to move forward, reject regressions and unknown blocks, and expose the latest safe/finalized checkpoint. A reorg may replace unfinalized history, but it must return a distinct `ErrResyncRequired` without mutating state when the common ancestor is missing, below the finalized checkpoint, or deeper than a caller-supplied retained-depth limit. Keep the current `Reconcile` API working; add a small bounded reconciliation entry point rather than putting RPC logic in the chain package.

Tests must cover monotonic finality, invalid marking, normal shallow reconciliation, finalized-history protection, depth-limit resync, atomic rejection, and checkpoint lookup. Commit as `feat: track finality and deep reorg resync`.

## Task 2: Add bounded Base log backfill

**Branch:** `soham/base-ingestion`

**Files:**

- Create: `internal/base/client.go`
- Create: `internal/base/backfill.go`
- Create: `internal/base/backfill_test.go`
- Modify: `go.mod`
- Modify generated dependency metadata if Go creates it

Define the narrow RPC interface needed around go-ethereum's `FilterLogs`. Implement a synchronous, context-aware backfiller for one configured contract address and topic set. It should request ascending inclusive block ranges, halve the current range after provider errors down to a configured minimum, grow it gradually after success up to a configured maximum, and emit logs in deterministic block/transaction/log order. Configuration errors and context cancellation must be returned clearly. Do not add workers, databases, retries with sleeps, WebSocket subscription management, ABI bindings, or a CLI in this task.

Tests must use a fake client and cover inclusive batch boundaries, adaptive shrinking and recovery, stable output ordering, invalid configuration, and cancellation. Commit as `feat: add adaptive Base log backfill`.

## Task 3: Add embargoed walk-forward splits and run IDs

**Branch:** `soham/walk-forward`

**Files:**

- Create: `python/src/bellwether_harness/splits.py`
- Create: `python/src/bellwether_harness/runs.py`
- Create: `python/tests/test_splits.py`
- Create: `python/tests/test_runs.py`

Implement a dependency-free expanding-window splitter over an already time-ordered sequence. Its configuration uses positive integer counts for initial training rows, embargo rows, test rows, and step rows. Every yielded fold must have training strictly before embargo and testing, never overlap test windows incorrectly, and stop cleanly when a full test fold no longer fits. Reject invalid configuration and non-monotonic timestamps.

Add deterministic run identity metadata containing Git SHA, canonical config hash, and data snapshot ID. Hash semantically identical mappings identically regardless of key order; reject empty identity fields. This code only identifies runs and splits rows—it must not compute features or train models. Tests cover exact fold boundaries, embargo separation, incomplete tails, invalid inputs, stable config hashing, and changed-input hashes. Commit as `feat: add embargoed walk-forward splits`.
